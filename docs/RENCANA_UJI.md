# Rencana Pengujian Sistem — Villa Joglo Masayu

Dokumen ini memuat skenario pengujian black-box, white-box, keamanan, dan integrasi web service sesuai dengan Bab IV Tabel 4.3 Proposal Proyek 3 (T-01 sampai T-18). Kolom hasil sengaja dikosongkan untuk diisi pada saat pelaksanaan demonstrasi pengujian formal.

---

## Tabel Skenario Pengujian (T-01 s.d. T-18)

| ID | Fitur / Skenario | Prosedur & Data Uji | Hasil yang Diharapkan | Hasil Pengujian |
|---|---|---|---|---|
| **T-01** | Informasi villa, galeri, kontak, dan peta | Buka halaman beranda (`index.php`) dan detail villa (`villa.php?id=joglo-wulung`). Periksa profil, tipe villa, harga, galeri, peta, dan tombol kontak. | Profil villa, tiga tipe villa, harga, galeri, testimoni, kontak, dan peta tertanam tampil dengan baik dan konsisten. | |
| **T-02** | Pendaftaran Pelanggan | Buka `daftar.php`, isi nama, email valid, nomor kontak, kata sandi $\ge 6$ karakter, dan konfirmasi cocok. Coba kirim field peran buatan. | Akun tersimpan dengan peran "pelanggan", otomatis login, dan field peran buatan dari luar diabaikan. | |
| **T-03** | Login dan logout pengguna (4 peran) | Uji login dengan kredensial Pelanggan, Pengelola, Pemilik, dan Admin; uji akun nonaktif; uji logout. | Pengguna berhasil masuk dan diarahkan sesuai peran masing-masing; akun nonaktif ditolak; logout membersihkan sesi. | |
| **T-04** | Reservasi dengan data valid | Pelanggan memilih Joglo Saren, check-in H+7, check-out H+9 (2 malam), dan 3 tamu. | Permintaan tersimpan berstatus "menunggu", kode reservasi diterbitkan, dan pesan berhasil tampil. | |
| **T-05** | Tanggal atau kapasitas tidak valid | Masukkan check-out sebelum/sama dengan check-in; check-in di masa lampau; atau jumlah tamu melebihi kapasitas maksimum villa. | Sistem menolak permintaan dan menampilkan pesan validasi yang menerangkan letak kesalahan. | |
| **T-06** | Semua unit sudah terpesan | Ajukan reservasi pada tipe villa dan rentang tanggal di mana seluruh unit telah memiliki reservasi berstatus "dikonfirmasi". | Sistem menyatakan tanggal tidak tersedia dan menolak penyimpanan reservasi baru. | |
| **T-07** | Pelanggan melihat reservasi (Proteksi IDOR) | Pelanggan A mencoba membuka rincian/riwayat reservasi milik Pelanggan B dengan memanipulasi parameter URL atau sesi. | Pelanggan A hanya dapat melihat rincian reservasi miliknya sendiri (`id_pelanggan = user_id`). | |
| **T-08** | Pengelola memproses reservasi | Pengelola mengonfirmasi satu permintaan dan mencoba mengonfirmasi permintaan lain yang bertabrakan saat unit sudah habis. | Transaksi database dengan kunci baris (`FOR UPDATE`) mencegah dua reservasi terkonfirmasi melebihi jumlah unit. | |
| **T-09** | Dashboard Pemilik (Read-Only) | Masuk sebagai Pemilik (`dashboard/pemilik.php`). Periksa statistik, ringkasan per status, tipe villa, dan nilai estimasi. | Jumlah dan estimasi nilai reservasi terkonfirmasi tampil akurat; dashboard tidak menyediakan tombol ubah/hapus status. | |
| **T-10** | Admin membuat dan mengelola akun staf | Admin membuat akun Pengelola dan Pemilik, menonaktifkan salah satu akun staf, dan mencoba menonaktifkan akun Admin sendiri. | Akun staf memperoleh peran yang ditentukan; staf nonaktif tidak dapat login; Admin dicegah menonaktifkan akunnya sendiri. | |
| **T-11** | Masukan berupa perintah SQL (SQL Injection) | Isi kolom input (nama, email, catatan) dengan teks injeksi seperti `' OR '1'='1` atau `'; DROP TABLE...`. | Masukan diproses murni sebagai teks biasa melalui PDO prepared statement; struktur database tetap utuh dan aman. | |
| **T-12** | Masukan berupa skrip berbahaya (XSS) | Isi kolom catatan reservasi atau nama dengan `<script>alert('XSS')</script>`. | Karakter di-escape secara aman menggunakan `e()` / `htmlspecialchars`; skrip tidak dieksekusi di browser. | |
| **T-13** | *(Dihapus - fitur eksternal dibatalkan)* | - | Dihapus atas arahan dosen pembimbing dan digantikan payment gateway. | - |
| **T-14** | *(Dihapus - fitur eksternal dibatalkan)* | - | Dihapus atas arahan dosen pembimbing dan digantikan payment gateway. | - |
| **T-15** | Tampilan antarmuka responsif | Uji buka website pada resolusi layar 360px (ponsel), 768px (tablet), dan 1024px+ (komputer desktop). | Teks, menu navigasi, kartu villa, dan tombol kontrol tidak terpotong serta proporsional pada seluruh ukuran layar. | |
| **T-16** | Jalur logika pemeriksaan ketersediaan | Telusuri cabang algoritma saat jumlah bentrok $<$ `jumlah_unit` dan saat jumlah bentrok $\ge$ `jumlah_unit`. | Cabang logika menghitung reservasi tumpang tindih secara matematis dan menghasilkan boolean ketersediaan yang benar. | |
| **T-17** | Pemeriksaan hak akses (Role Authorization) | Akses `dashboard/*.php` tanpa login atau menggunakan akun Pelanggan. | Permintaan tanpa hak akses ditolak dan dialihkan kembali ke `login.php` atau `index.php` disertai pesan peringatan. | |
| **T-18** | Perhitungan estimasi nilai reservasi | Uji perhitungan durasi menginap campuran (malam weekday + malam weekend + extra bed). | Estimasi dihitung akurat dari formula durasi dikalikan tarif snapshot pemesanan, dan diberi label non-pembayaran aktual. | |

## Tabel Skenario Pengujian Tahap 11 (T-55 s.d. T-67) — Kalender Ketersediaan & Reservasi Offline

| ID | Fitur / Skenario | Prosedur & Data Uji | Hasil yang Diharapkan | Hasil Pengujian |
|---|---|---|---|---|
| **T-55** | Kalender menandai tanggal penuh untuk semua pengguna | Terdapat unit villa yang terisi penuh pada tanggal tertentu (terkonfirmasi + blokir $\ge$ `jumlah_unit`). Buka halaman detail villa, formulir reservasi, atau kalender hunian. | Tanggal yang terisi penuh ditandai dengan sel abu-abu, teks "penuh", coretan visual, dan dinonaktifkan dari pilihan check-in. | **LULUS** (Unit terkonfirmasi penuh langsung terdeteksi sebagai `'penuh'` pada seluruh antarmuka) |
| **T-56** | Rentang tanggal yang melewati tanggal penuh ditolak | Pelanggan atau staf memilih tanggal check-in sebelum tanggal penuh dan tanggal check-out setelah tanggal penuh. | Sistem menolak pilihan rentang tersebut, menampilkan pesan kesalahan yang menyebutkan secara spesifik tanggal penuhnya, dan mereset pilihan tanggal. | **LULUS** (Deteksi tumpang tindih rentang menolak penyimpanan dan menampilkan peringatan tanggal penuh) |
| **T-57** | Status menunggu tampil sebagai peringatan dan tidak memblokir unit | Terdapat reservasi berstatus `'menunggu'` pada tanggal tertentu. Pengguna lain mencoba memilih tanggal tersebut. | Tanggal menampilkan penanda pola bergaris dan label "menunggu" disertai peringatan, tetapi tetap dapat dipilih karena status menunggu tidak memblokir unit (F-08). | **LULUS** (Status `'menunggu'` berstatus peringatan tanpa mengurangi sisa unit terkonfirmasi) |
| **T-58** | Proteksi privasi API kalender publik | Panggil `api/cek-ketersediaan.php?mode=kalender&tipe=1&dari=...&sampai=...` tanpa login. Periksa payload respons JSON. | Respons hanya berisi status per tanggal (`tersedia`, `menunggu`, `penuh`) tanpa memuat nama tamu, kontak, id reservasi, maupun data pribadi lainnya. | **LULUS** (Payload bersih dari data pribadi tamu, cache 30 detik aktif) |
| **T-59** | Pencatatan reservasi offline oleh Pengelola | Pengelola menginput tamu walk-in / WhatsApp / telepon dengan data valid. | Reservasi langsung tersimpan berstatus `'dikonfirmasi'`, dan tanggal terkait seketika menjadi penuh di kalender seluruh pengguna. | **LULUS** (Reservasi offline tersimpan dan langsung mengurangi ketersediaan real-time) |
| **T-60** | Reservasi offline ditolak bila unit penuh | Pengelola mencoba mencatat reservasi offline pada tanggal yang sudah penuh terisi. | Sistem mendeteksi unit penuh dan menolak penyimpanan dengan pesan kesalahan yang jelas. | **LULUS** (Validasi ketersediaan server menggagalkan pembuatan reservasi pada jadwal penuh) |
| **T-61** | Pencegahan balapan (*race condition*) reservasi | Dua proses bersamaan mencoba mengamankan unit terakhir (konfirmasi online vs submit reservasi offline). | Kunci baris transaksi (`SELECT ... FOR UPDATE` pada `tipe_villa`) bertindak sebagai mutex; hanya satu permintaan yang berhasil dan permintaan kedua ditolak karena unit habis. | **LULUS** (Transaksi ACID dengan `FOR UPDATE` menjamin isolasi dan mencegah *double booking*) |
| **T-62** | Deteksi bentrok permintaan menunggu | Reservasi offline dikonfirmasi pada tanggal di mana terdapat permohonan online menunggu. | Permohonan online yang kini bertabrakan ditandai badge "Bentrok" di dashboard Pengelola, dan tombol konfirmasinya ditolak oleh server. | **LULUS** (Status bentrok terdeteksi otomatis, server menolak konfirmasi permohonan yang bertabrakan) |
| **T-63** | Pencatatan pembayaran tunai sekaligus bersifat atomik | Pengelola mencatat reservasi offline dengan mencentang opsi "Catat pembayaran tunai sekarang". | Reservasi dan pembayaran tunai manual tersimpan secara atomik dalam satu transaksi; jika salah satu gagal, keduanya dibatalkan. | **LULUS** (Reservasi offline berstatus dikonfirmasi dan pembayaran berstatus lunas tersimpan secara utuh) |
| **T-64** | Pembatalan reservasi offline | Pengelola membatalkan reservasi offline belum lunas (dengan alasan). Uji coba membatalkan reservasi yang sudah lunas. | Reservasi offline belum lunas berubah status menjadi `'dibatalkan'` dan tanggal kembali terbuka; pembatalan reservasi yang sudah lunas ditolak server. | **LULUS** (Reservasi belum lunas berhasil dibatalkan dan membuka tanggal; reservasi lunas terlindungi) |
| **T-65** | Pemblokiran tanggal villa | Pengelola membuat blokir tanggal untuk pemeliharaan villa. Uji coba blokir yang memotong reservasi terkonfirmasi, lalu batalkan blokir. | Blokir berhasil menutup tanggal menjadi penuh di kalender; blokir ditolak jika memotong jadwal reservasi aktif; pembatalan blokir membuka kembali tanggal. | **LULUS** (Tabel `blokir_tanggal` menutup ketersediaan; soft-cancel memulihkan tanggal) |
| **T-66** | Otorisasi hak akses peran | Coba akses API reservasi offline dan blokir tanggal tanpa login atau dengan peran Pelanggan / Pemilik. Buka kalender hunian sebagai Pemilik dan Admin. | Permintaan simpan/ubah ditolak (403 Forbidden); Pemilik dan Admin dapat mengakses kalender hunian dalam mode *Read-Only* tanpa tombol aksi perubahan. | **LULUS** (`require_role` membatasi modifikasi data hanya untuk Pengelola/Admin; Pemilik read-only) |
| **T-67** | Responsivitas, dwibahasa, dan aksesibilitas kalender | Uji tampilan kalender dan kalender hunian pada lebar layar 320px (mobile agenda view) dan 1024px+ (desktop grid view); navigasi keyboard (panah/Enter/Esc); bahasa ID dan EN. | Antarmuka menyesuaikan tata letak tanpa scroll horizontal pada body; teks dan format tanggal dwibahasa; elemen grid memiliki atribut ARIA lengkap. | **LULUS** (Tampilan mobile bertransformasi menjadi agenda vertikal; navigasi keyboard dan lokalisasi Intl bekerja sempurna) |
